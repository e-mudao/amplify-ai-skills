# 工具验证协议

这是逻辑记录格式，不是可直接调用的 MCP API。运行时映射到宿主已暴露的实际工具名、参数 schema、权限和资源限制。不能把本文件中的字段当作工具存在的证据。记录用于核验追溯；默认对用户只呈现相关结论、证据与局限，完整账本仅在演示、调试或审计请求中展示。

## 能力发现

按需确认工具是否可用、输入是否存在、访问是否授权；不因列出某连接器而探测无关账户。能力状态：available / unavailable / unknown；有工具但无数据不算可验证。

## CheckSpec

每项验证先写明：

```yaml
id: check-identifier
claim: 待检验的具体断言
inputs: [{source: 实际路径或来源标识, provenance: user|system|synthetic, scope: 范围}]
method: 计算或核验方法及适用条件
binding: 实际工具名与符合其 schema 的参数；未发现则 null
oracle: 独立参考值/预先确定的判定规则/保留数据集
limits: {time: 建议或用户预算, calls: 调用上限, side_effects: none或获授权范围}
pass_condition: 可判定的通过标准
failure_condition: 失败、缺失及停止条件
```

调用后的 `CheckResult`：

```yaml
id: 同一检查标识
status: planned|passed|failed|blocked|not_applicable
evidence: 工具实际返回的输出、来源或本地结果路径；无则 null
scope: 此结果能证明什么
limitations: 不能证明什么
```

- planned：尚未运行；blocked：缺能力、输入、授权或依赖。工具执行异常记 failed，并说明未能判定业务断言；依赖缺失另记 blocked。
- passed：实际输出满足既定规则。无输出/没有报错不自动等于通过。
- not_applicable：检查与该主张无关，说明原因。
- 不运行时只给计划，不生成看似真实的调用日志、时长、分数或证据路径。

## 工具路由

| 问题 | 合适接口 | 证据与局限 |
|---|---|---|
| 算数、转换、对账 | Python/实际解释器或 SQL | 对照原始记录或独立期望值；不能证明输入真实 |
| 本地文件/编译/测试 | Bash/终端及真实测试工具 | 保存失败与输出；生成代码自己的断言不是充分外部裁判 |
| 当前事实、规则、先例 | WebSearch/浏览器/来源连接器 | 读取来源、记录日期与支持范围；搜索摘要不自动等于权威证据 |
| 用户业务记录 | 已授权 MCP/只读 API | 验证字段、范围、权限；不能编造连接成功 |
| 行为改善、预测效果 | 留出样本、历史对照或真实用户试验 | 防时间泄漏；报告样本量及误差；预测表现不能直接证明因果 |

## 退化路径

1. 可用且相关：在授权范围内执行最小检查。
2. 缺工具：给可运行检查步骤与期望判定方式，标 planned/blocked。
3. 缺数据：给最小字段、时间范围和来源；可交付提示词，不声称事实已验证。
4. 失败：保留真实错误；最多一个合理替代。Python 改手工只能降低为人工复核，不能仍称自动验证。
5. 合成数据：显式标 synthetic，结论仅限协议/算法流程。禁止把合成指标冒充生产效果。

编译不得为了“验证”越权安装、抓取生产数据或创建调度。对实际调用施加超时、调用次数、网络/写入白名单需要宿主实现；提示词本身无法强制隔离。
