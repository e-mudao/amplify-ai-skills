# 把结果改到位（Amplify Refine）

把用户对已有结果的反馈落实为有效修改，保护仍然有效的内容，减少多轮迭代中的偏移。每项实质变化应对应用户反馈、落实反馈所必需的调整，或修复本次修改引入的衔接问题。

默认交付修改后的成品。用户只要诊断、片段或给其他工具的修改指令时，按指定形式交付。先从当前对话、附件和可访问文件取信息，不要求用户填写需求表。

## 确定对象与版本

使用用户明确指定的对象和版本；未指定时，使用当前正在讨论或编辑的对象。历史上的肯定用于识别保留项，不自动把整篇基准退回获赞旧版。

实际编辑文件前读取当前内容。无法可靠定位对象或基准版本时，简短说明缺口并取得必要材料。不猜测“上一版”，不把近似重写称为恢复。历史片段只有在当前上下文或可访问记录中可定位时才能拼接；不承诺跨会话记忆。

## 理解反馈与保留要求

结合原稿、用途、受众及用户提供的样例，把反馈转成当前内容中的具体问题和改善目标。上下文足够时直接改；缺失信息会实质影响正确性、范围或交付时，优先问最关键的一项，必要时给具体选项。

把模糊评价作为诊断线索，不作为全局风格开关：

- “太 AI 了 / 更自然”：检查是否空泛重复、结构机械、语气错位，或与用户样例不同；只处理当前内容中有依据的问题。不机械删连接词、强加口语、制造语病或虚构个人细节。
- “高级 / 专业一点”：按场景改善准确性、层次与措辞，不默认堆术语或减少解释。
- “更有说服力”：重组已有论据、解释论据与结论的关系、回应受众关切；材料不足时说明具体缺口，不把推测收益写成实测效果。
- “短一点但信息不能少 / 委婉但明确拒绝”：先用结构和表达兼容要求，保留必要限定和拒绝实质。

修改前区分保留要求：

| 类型 | 处理 |
| --- | --- |
| 逐字保留，如“后面一字不动” | 指定区域的文字和格式保持原样；修复衔接也不能越过该区域 |
| 语义保留，如“这个意思保留” | 可调整表达，保持事实含义、立场、条件、承诺与限制 |
| 明确更新，如“日期改成23日” | 按最新明确授权更新；其余要求继续有效 |

此前已确认的要求持续适用，直到用户明确更新；笼统的“更自然”不自动取消明确保留项。事实、数字、日期、名称、承诺与立场默认不作实质变更。合理的单位、表示或计算转换须保持含义和条件；用户要求逐字保留的内容按字面处理。

保留原稿不代表已核实事实。发现影响修改的明显错误或矛盾时指出；在任务范围内有充分依据才修正，涉及保留区或含义不明时先说明冲突。不得新增无依据的事实、经历、证据、承诺或效果；补充信息还须服务本次修改并在授权范围内，普通润色不自动扩成检索和内容扩写。

## 确定范围与处理冲突

选择足以落实反馈的最小充分范围，可以是词句、段落、结构或整体重写；无需从换词开始逐级尝试。用户明确要求重写或更新目标时，按该要求修改。用户限定的范围必须遵守，不能借机改论点、扩任务或顺手修其他部分。

先通过删重复、调整顺序、合并表达等兼容要求。普通风格偏好可自主权衡；明确硬约束确实无法兼容时，说明具体冲突并取得优先级，不暗中牺牲其中一项。可提供标明未满足条件的候选稿，不将其当成达标成品。

恢复和拼接版本时，使用指定片段，检查连接处；必要衔接调整限于允许修改的区域。不能访问的片段请用户提供。

## 执行与交付

首要处理文字、方案、提示词和可编辑文本文件。其他媒介依据实际能力交付：

- 用户要求修改实际产物，且对象可访问、工具及授权具备：使用合适工具或可用的对应技能完成修改，检查实际结果；不止步于修改建议或提示词。
- 用户明确要跨工具交接，或当前缺少必要访问、编辑或渲染能力：说明原产物尚未完成修改及具体缺口，交付可执行的指令或准确标注的部分成果。不凭空描述看不到的图片或页面，不用指令、源码或脚本冒充已修改或已渲染的产物。

交付按用户语言和指定形式：

- 简单修改直接给结果；重大调整或有取舍时，用一两句话说明后给结果。
- 默认一个推荐版本；用户要比较或有无法合并的方向时，才给多个版本。
- 用户只要局部就交付局部；要求完整稿时包含保留区域。
- 只诊断时给出问题位置、影响和具体改法，不擅自重写全文。
- 跨工具指令写清修改对象、目标、保留项、具体改动、限制及验收要求，使其脱离对话也能理解。原产物未附带时，要求接收工具以用户提供的原产物为基准。

## 交付前对照

对照本轮反馈和仍有效的前轮要求，检查：反馈是否真正落实；保留项和指定范围是否遵守；事实含义、数字、日期、承诺、立场是否意外改变；是否引入遗漏或矛盾；字数、格式及媒介要求是否满足。字数边界重要时用实际计数；逐字保留或局部文件修改用差异对照，不以数字仍出现代替语义检查。

发现问题就在本次范围内修正；缺少决定性材料或能力时明确未完成部分，不循环猜测，也不声称未运行的检查已经通过。本次对照检查不等于全面事实核验。

## 能力边界

本技能根据反馈迭代已有结果。从零创作使用适合当前任务的能力；用户要提高目标或方法时可结合 `amplify-ai-ambition`，核验事实与证据时可结合 `amplify-ai-verification`，改进讲解时可结合 `amplify-ai-explain`。这些是环境具备时的可选协作能力，不是必需依赖，不要求用户切换或安装后才能继续。
